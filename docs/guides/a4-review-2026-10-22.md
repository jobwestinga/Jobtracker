# A4 correctness review — 22 October 2026

Reviewed the implementation through `5034a29` against the
[overhaul guide](a4-native-mac-overhaul.md), current service contracts and the
[earlier evidence](a4-evidence.md). The task was review and defect correction;
no remaining overhaul features, production installation, phone deployment or
default switch were authorized by this review.

## Conclusion

The separation between the native UI and the retained Python engine is sound,
and the original focused and native checks passed. They did not cover several important
failure and draft-preservation cases. The corrections below address those
defects with regression coverage. They do not establish complete native UI
parity or close the outstanding hands-on acceptance gates.

The review covered engine startup/locking, command transactions, receipts,
native bridge/journal, feature stores and editor state, changed phone code,
packaging and installer integration. Tests use disposable synthetic stores;
the review did not open or migrate the user's production data.

## Findings corrected

| Finding | Correction and evidence |
| --- | --- |
| Qt imported the eager SQLite singleton before taking the store lock | Delay MainWindow import until ownership is acquired. A subprocess regression holds the native lock and verifies that importing/refusing the Qt entry point creates no database. |
| Receipt migration backed up only stores with Subjects | Check independent Weight, Goals, settings, aliases and pending operations too. Weight-only, Goals-only and settings-only cases now produce readable pre-migration backups. |
| A mutation could commit before its oversized response was rejected as invalid | Validate the response frame inside the outer transaction before committing its receipt. The regression verifies rollback of the row, outbox entry and receipt. |
| A replayed refusal/missing-target result looked successful to Swift | Decode the original receipt outcome and reason. Successful replays remain successful; refused/missing replays retain their domain meaning. |
| Retrying a timed-out request could overwrite its captured parameters or pending continuation | Journal captures are immutable. An identical retry preserves the original ordering; changed parameters cannot replace it. Unresolved mutations block new mutations, and a retry resends the original capture. A real suspended-engine test verifies the resulting rows and journal. |
| Device identity alone could send newly journaled requests to a copied store | New envelopes also capture the canonical database path and replay only against that path. Original records are retained; legacy pathless pilot records retain compatibility and must be resolved on their original store before it is moved/copied. |
| Late creates could leave editors creating another entity or erase newer input | Route late results to the originating editor, adopt the saved entity/milestone identities and retain newer fields. Live-engine checks exercise an interrupted Goal create and session create followed by newer edits. |
| An explicitly chosen old session disappeared outside the first history page | Fetch and retain that exact selected UID without loading all history. The regression creates more than 200 records and opens the oldest one. Stale load-more responses are ignored. |
| Archived session owners were missing from the initial subject selector | Derive required archived subjects from the freshly loaded rows and explicit scope, not the previous empty list. |
| Refresh discarded unsaved session input when a target disappeared | Clear the invalid selection while retaining the draft and explaining its state. Saving requires the original target to remain selected; a detected conflict must be resolved first. |
| Failed token writes left changed SQLite sync settings, and the native panel could close/erase the token anyway | Roll back settings when token replacement fails and restore the prior token if the DB commit fails. Keep Settings open and retain the typed token. Sync Now does not proceed after a failed configuration save. |
| A weight save completing after a date/target change could attach the old UID to the new draft | Count date and edit-target changes as draft revisions, preserve newer targets and handle late weight receipts by their original revision. Failed deletes retain editing identity. |
| Date fields silently normalized invalid dates/offsets and DST-gap values | Validate civil fields explicitly, reject zoned input and preserve entered naive timestamps. Display uses civil fields; Python remains responsible for session duration validation, avoiding absolute-time DST reinterpretation. |
| The ninth and later overlapping agenda sessions were assigned to the same lane | Preserve every assigned lane on both native and phone. Native narrow-column geometry stays positive. New tests verify 12 distinct targets; phone shell becomes v27. Existing times and rows are unchanged. |
| Close routes could bypass in-flight-save protection; failed quit confirmation was treated as permission to exit | Apply dismissal guards consistently to Close and Escape, including nested panels. Require a positive engine quit result. A native state check verifies both panel close routes. Real application termination remains part of the manual window-lifecycle pass. |
| Recovery text exposed an implementation suffix | Remove the two user-visible `running.value` strings. |
